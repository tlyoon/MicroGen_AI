# PR268 — chapter-wide external WAV intake and private video candidates

Original MicroGen_AI only, HP-only execution. This step advances the six-section PR267 source/science/slide/voice request handoff toward reusable audio/video delivery. It does not synthesize a voice, select a provider, invoke a local language model or a paid API, grant distribution rights, or approve publication.

## Reuse, not another per-PDF fix

`microgen_private_chapter_audio_video.py` uses PR267 chapter and per-section SHA-locked voice requests, PR265 `audit_portable_audio_import` (original text SHA, WAV SHA, bounded PCM and duration checks), and the existing `build_demo_video` offline FFmpeg/PDF-render/midpoint-frame verifier. It does not repeat the previous mathematical or source figure semantic campaign. The chapter receipt's exact verified source/science identity is required, and each original source PDF, narration JSON and rendered teaching PDF are freshly SHA-compared, without reauthoring or rerendering them.

**Phase 1 — prepare private capture plan:** Provide `--chapter-bundle` (PR267 private accepted directory), `--source-manifest` (original six-section private chapter input manifest) and a fresh `--new-private-plan`. The plan contains the six original section IDs, original source and slide/narration paths, and the chapter readiness receipt SHA. It deliberately sets every `audio_dir` and `capture_manifest` to null. The plan is sensitive because it contains authorized local paths and must remain on HP, never in public GitHub/Drive.

**Phase 2 — return existing externally produced WAVs:** For every section, place exactly `slide01.wav`, `slide02.wav`, etc. in its own PRIVATE audio directory, and fill the matching capture manifest from PR267's blank `capture_templates/section_*_blank.json`. Set `declared_provider` and `declared_voice` to truthful descriptive labels, and supply the exact SHA256 of each WAV. The original template's `source_text_sha256` and `voice_input_handoff_sha256` must never be changed. Fill only that section's `audio_dir` and `capture_manifest` paths in a copy of the private plan. Audio filenames are not to be shared with unapproved services or publicly uploaded. Provider label is descriptive, not independently authenticated.

Run `--chapter-bundle <private folder> --capture-plan <completed private plan> --new-private-output <fresh private folder>` for an all-or-nothing WAV technical audit and one private chapter readiness receipt. Add `--render-private-videos` to additionally render each section's PRIVATE, NOT-PUBLISHED H264/AAC candidate from existing PDF slides and verified WAVs, checking every slide midpoint against its original PDF page. No output is made if any member fails, and an existing output folder is never overwritten. Video assembly uses no generated speech: all WAVs must already be present.

The final private output contains `chapter_private_audio_video_receipt.json` with hashes/counts/negative approval flags. When video is enabled, it additionally contains `section_videos/section_1_1_PRIVATE_NOT_PUBLISHED.mp4` etc. Section candidates remain private. This does not promise or create a single combined chapter-length MP4; the six independent section videos are the chapter-wide batch output. A separate combined publisher cut can be built after verified formal audio and academic review.
