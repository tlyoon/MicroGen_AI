# Measured active-element highlighting — draft engineering contract

Project scope: original Gemini-API MicroGen_AI, not MicroGen_AI_Web.

## Verified gap

The current gen_video_v22.py renders a static slide PNG for the complete slide WAV.
Previously accepted private lectures therefore do not establish narration-synchronized
within-slide highlighting. Do not infer timing from a proportional word-count
division of the whole-slide WAV, or reinterpret old private acceptance receipts
as evidence of this missing feature.

## Input manifest

The new, unmerged microgen_timed_highlight_contract.py module validates
.microgen_timed_highlights.json in an isolated stage folder.

- schema_version: 1
- timing_method: measured_ordered_pcm_chunks
- publication_allowed: false
- slides_pdf_sha256: actual full PDF hash
- script_tts_sha256: actual narration sidecar hash
- slides: all ordered slide rows, each with exact PDF and WAV hashes.
- Each slide cue has element_id, pdf_text, spoken_text, pdf_bbox (four page-point
  coordinates), audio_chunk, and audio_chunk_sha256.
- The chunk path must match highlight_chunks/slideN_cueM.wav and the correct
  slide/element order.

The source producer must synthesize each cue with the configured Gemini
Flash-Lite voice, then form the complete slide WAV from the exact ordered PCM
samples. The validator independently rechecks sample-rate/channel matching,
ordered sample-for-sample reconstruction of the whole WAV, SHA hashes, visible
PDF-text containment, script-text coverage in order, rectangle bounds and
symlink/path security. It does not use Whisper or ASR.

The FFmpeg drawbox filter is time-gated to measured PCM frame intervals.
The optional production path in gen_video_v22.py now renders measured cues at
10 fps when a fully validated manifest exists. The legacy static renderer
remains the default without a manifest. Timed fragments use a separate
manifest-hash-bound cache; video-part and private acceptance inputs include
the cue-chunk SHA hashes. Legacy multipart delivery is blocked for timed cues
until it has equivalent verification.

Dell-115 synthetic FFmpeg testing independently decoded the first and second
cue intervals and confirmed a visible yellow highlight switched between the
two source-grounded text regions. This verifies the overlay primitive on a
controlled example. It does NOT prove cue generation or synchronization on
a real lecture. The validator deliberately reports
visual_highlight_rendering_verified=false and
spoken_word_to_element_alignment_verified=false. No new rights are granted.

## Integrated opt-in measured-cue TTS producer

The original `text_to_speech_v25.py` stage can now use a verified
`.microgen_timed_cue_plan.json` in its isolated work directory. Set
`MICROGEN_TIMED_CUES=1` to request an automated **offline**, conservative
source-PDF/text-overlap proposal before any paid TTS call, or supply a plan
generated by that same checked planner. Unsupported semantic paraphrases
produce a clear blocker, not invented element coordinates or fake acceptance.

Before paid requests, the opt-in stage verifies all slide-page PDFs using the
original PyPDF2 slicer, preserving previously accepted pages instead of
overwriting them later. The plan must cover every slide and all the narration
text in order. Every cue is backed by actual PDF text and a rectangle inside
its source page. All cue texts form **one** bounded batch (at most 120 cues)
using the existing `microgen_flash_tts.render_batch()`: Gemini Flash-Lite
with the consistent Kore voice by default, whole-batch Gemini Flash fallback,
and no unapproved Cloud TTS. Scientific pronunciation normalization and the
existing lexical/QA preflight are reused.

A complete slide WAV is created by concatenating **exact PCM** from the
verified cue WAVs. Source slide PDF/script hashes, normalized narration,
waveform provenance, pronunciation risks and offline QA evidence are
validated in a private staging directory before any stage output is installed.
Files are created using exclusive hard links; preexisting audio and accepted
files are never overwritten. If a crash leaves partial outputs, future runs
refuse to silently replace them. Current static TTS remains the default when
the opt-in/verified plan is absent. TTS dependency fingerprints include the
cue plan and opt-in mode so old static audio cannot be misidentified.

This is a measured-cue *producer* and **not** an independent guarantee that
the Gemini voice actually spoke each phoneme at the expected point.
Fail-closed acoustic checks and decoded-video synchronization must still run.

## Remaining development milestones

1. Add a general source-grounded semantic mapping mechanism for narration
   paraphrases that do not share enough literal words with the PDF. Preserve
   model-independent verification of bounding boxes, slide/order identity,
   source hashes and non-invented mathematical statements. Do not repeatedly
   tune the planner against one Serway PDF.
2. Independently decode the complete MP4 before, during and after each cue,
   verifying highlight transitions, correct targeted regions and bounded
   drift using a SHA-bound synchronization receipt. The synthetic probe is
   useful regression evidence, not a real lecture acceptance receipt.
3. Enforce the synchronization receipt at a separate publication-readiness
   gate, without retroactively reclassifying existing static-video technical
   acceptance, altering other scientific/audio gates or granting rights.
4. Complete a private end-to-end multi-source acceptance campaign after
   the general source-mapping and timing verification stages are ready.
